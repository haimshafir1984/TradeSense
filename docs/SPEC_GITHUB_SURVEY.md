# סקר GitHub ציבורי — איפיון

תאריך: 2026-08-12
סטטוס: מומש
פלט: `docs/GITHUB_SURVEY.md` (נוצר מחדש בכל ריצה)

## 0. למה

אחרי שהמסחר בפועל לפי המלצות המערכת לא נתן תוצאות, עלתה השאלה: איך אחרים בנו מערכות המלצות מניות, ומה קיים בקוד פתוח שאפשר ללמוד ממנו. הסקר הזה עונה על השאלה **"מה קיים בחוץ"** — ולא על השאלה "מה עובד", שהיא שאלה אחרת לגמרי שהסקר הזה מפורשות לא יכול לענות עליה.

## 0.1 מה זה לא

- **לא המלצה לאמץ** שום פרויקט מהרשימה.
- **לא חוות דעת על איכות קוד.** הסקר קורא מטא-דאטה בלבד (כוכבים, תיאור, תגיות, commit אחרון, רישיון) ואינו קורא שורת קוד אחת. הוא לא יכול לזהות lookahead bias, backtest שקרי, או פרויקט שלא עובד.
- **לא אוטומטי.** CLI ידני בלבד, כמו כריית האנומליות. אין route, אין scheduler, שום דבר באפליקציה הרצה לא קורא לו.

הטענה היחידה שהנתונים תומכים בה: *"זה קיים, ומתוחזק/לא מתוחזק"*.

## 1. ארכיטקטורה — שני שלבים

הניסיון הראשון נכשל והביא **0 תוצאות**. הסיבה: חיפוש הריפוזיטוריז של GitHub מחפש בשם/תיאור/תגיות בלבד (**לא ב-README**), וכל המילים בשאילתה מחוברות ב-AND. שאילתה תיאורית כמו `position sizing stop loss risk management trading` מצמצמת את עצמה לאפס. מדידה בפועל (2026-08-12):

| שאילתה | תוצאות |
|---|---|
| `"position sizing" trading` | 1 |
| `market regime detection` | 0 |
| `news sentiment trading` | 0 |
| `topic:algorithmic-trading` | 111 |
| `topic:finance` | 262 |

לכן המבנה הוא **קציר רחב ואז סיווג מקומי**:

1. **קציר** — 8 שאילתות `topic:` (`algorithmic-trading`, `quantitative-finance`, `trading-strategies`, `backtesting`, `stock-market`, `technical-analysis`, `quantitative-trading`, `trading-bot`), עם סף `stars:>=150` ו-`pushed:>=` בחלון של 540 יום. מיזוג ל-set ייחודי.
2. **סיווג** — התאמת מילות מפתח מקומית מול התיאור/התגיות, לתוך 10 קטגוריות שמוגדרות לפי **הפערים של TradeSense** (יציאה וסיכון, מנועי backtest, ניתוח פקטור, למידה מתוצאות, תוך-יומי, מונע-אירועים, משטר שוק, סורקים, סוכני LLM, שכבת נתונים) — ולא לפי חלוקה גנרית של "מסחר".

תגיות GitHub הן slugs עם מקפים (`position-sizing`) בעוד תיאורים משתמשים ברווחים; שני הצדדים עוברים נרמול מקפים→רווחים לפני ההשוואה, אחרת כל התאמה מבוססת-תגית נופלת בשקט.

## 2. הרצה

```
npm run research:github --workspace server [-- --min-stars=150 --max-age-days=540]
```

מכסת החיפוש של GitHub ללא אימות היא 10 בקשות לדקה, ולכן יש השהיה של 7 שניות בין שאילתות (2.5 שניות אם מוגדר `GITHUB_TOKEN` ב-`.env`, שמעלה את המכסה ל-30). `GITHUB_TOKEN` אופציונלי לחלוטין — הסקר עובד בלעדיו.

## 3. קבצים

- `server/src/services/research/githubSurveyService.js` — כל הלוגיקה. פונקציות טהורות (`classifyRepository`, `assessRepository`, `dedupeAndRank`, `repositoriesForGap`, `renderReport`) מופרדות מהרשת (`searchRepositories`, `runSurvey`), כדי שיהיו ניתנות לבדיקה בלי לגעת ב-GitHub.
- `server/scripts/surveyGithub.js` — CLI. הבעלים היחיד של כתיבה לדיסק.
- `server/test/githubSurveyService.test.js` — 9 בדיקות, אף אחת לא פונה לרשת.

## 4. דגלי אזהרה

כל ריפו מסומן בדגלים שנראים ממטא-דאטה בלבד — במכוון מוצגים ולא מוסתרים, באותו עיקרון כמו טבלת "תבניות שנפלו ב-holdout" בדוח האנומליות:

- ארכיון (הפרויקט הוקפא)
- ללא commit מעל שנה (נטוש לכאורה)
- ללא רישיון — חוסם שימוש חוזר בקוד, גם אם הפרויקט מעניין
- פחות מ-200 כוכבים — כמעט ללא ביקורת עמיתים

## 5. ממצאי הריצה הראשונה (2026-08-12)

352 ריפוזיטוריז ייחודיים. הממצא המרכזי הוא **היכן אין קוד פתוח**, לא היכן יש:

- **משטר שוק: תוצאה אחת בלבד** (ועוד כזו עם 153 כוכבים, ללא רישיון). הדבר שהכי יכול לשפר תוחלת — לדעת מתי לא לסחור — הוא כמעט ללא תקדים בקוד פתוח.
- **יציאה/סטופים/גודל פוזיציה: 23 תוצאות, אבל כמעט כולן אופטימיזציית תיק** (PyPortfolioOpt, Riskfolio-Lib, skfolio) — שזו בעיה אחרת לגמרי מחוקי יציאה ברמת העסקה הבודדת. גם כאן, הפער הגדול ביותר של המערכת כמעט ללא תקדים ישיר.
- **מנועי backtest: 98 תוצאות** — הקטגוריה הצפופה ביותר בהפרש גדול. שם מרוכז רוב המאמץ בקוד הפתוח.
- **128 מתוך 352 (36%) לא נכנסו לאף קטגוריה** — בוטים גנריים ללא ייעוד ברור.
- **53 ללא רישיון כלל**, ורבים תחת GPL/AGPL — מגבלה אמיתית אם אי פעם ירצו לשלב קוד בפריסה.

המסקנה המתודולוגית: הצפיפות בקוד פתוח מתרכזת בדיוק במקומות שקל למדוד בהם הצלחה (מנוע backtest או בוט "עובד" או לא), ונעלמת במקומות שדורשים הכרעה סטטיסטית אמיתית. זו עדות עקיפה לכך ששני הפערים שזוהו כחשובים ביותר הם קשים — לא שנשכחו.
